# 数据更新指南

> 一句话：**使用率用远程热更新（改 JSON 不用提审），图鉴用本地脚本 + 重新发布。**
> 工具入口只有一个：`node scripts/update-data.js`

---

## 0. 先看清楚：哪些数据会变、该怎么更

| 数据 | 文件 | 变化频率 | 建议更新方式 |
| --- | --- | --- | --- |
| 使用率（单打 / 双打） | `data/usage.js` | 每月 | **远程 JSON 热更新**（不用重新提审）；也可随版本发布 |
| 图鉴（宝可梦 / 招式 / 特性 / 道具） | `data/pokedex.js`、`data/items.js` | 随游戏版本 | 本地脚本 + 重新上传发布 |

小程序端的远程热更新**已经实现**（`utils/usage-service.js`）：启动时先用本地/缓存数据渲染，再后台请求远程 JSON，版本号更新就替换并缓存。你只需要一个 HTTPS 地址。

---

## 1. 命令速查

```bash
# 看现在是什么版本、数据新不新鲜
node scripts/update-data.js status

# 使用率：拉 Smogon 最新月份（单打 BSS）
node scripts/update-data.js usage --dry-run     # 先看差异，不写文件
node scripts/update-data.js usage               # 确认后写入

# 使用率：双打也换成 Smogon VGC（默认沿用现有 Limitless 数据）
node scripts/update-data.js usage --doubles smogon

# 使用率：指定月份 / 分位
node scripts/update-data.js usage --month 2026-10 --cutoff 1760

# 图鉴：OP.GG 抓宝可梦 + 招式 + 特性（+ 可选道具）
node scripts/update-data.js pokedex --dry-run
node scripts/update-data.js pokedex
node scripts/update-data.js pokedex --sprites   # 同时下载缺失的精灵图
node scripts/update-data.js pokedex --items     # 同时更新道具表

# 数据自检 / 生成热更新包 / 校验写出格式
node scripts/update-data.js check
node scripts/update-data.js publish --out dist/usage.json
node scripts/update-data.js selftest
```

| 参数 | 作用 |
| --- | --- |
| `--dry-run` | 只计算并打印差异，不写文件 |
| `--refresh` | 忽略 `.cache/`，强制重新下载原始文件 |
| `--month YYYY-MM` | 指定 Smogon 月份（默认取索引里最新的） |
| `--cutoff 1760` | 指定分位（默认沿用现有 META） |
| `--doubles smogon\|keep` | 双打数据来源（默认 keep） |
| `--names` | 图鉴名称也采用官方最新写法（默认保留现有译名） |
| `--include-gender-forms` | 收进「能力值完全相同、只有性别差异」的形态 |
| `--items` / `--sprites` | 同步道具表 / 下载缺失精灵图 |

## 2. 数据源与换算（为什么数字能对上）

### 2.1 单打使用率：Smogon 月度 chaos

```
https://www.smogon.com/stats/2026-10/chaos/gen9championsbssregmc-1760.json
```

- `usage` 是 0–1 的小数，乘 100 即使用率；名次按使用率排序。
- 特性/道具/招式/性格/努力值的原始值是**加权计数**，同一只宝可梦所有特性之和 = 它的总样本，因此：

  `百分比 = 该条目的值 ÷ 所有特性值之和 × 100`

  这样特性之和恰好 100%，招式则是「携带率」（可叠加，四项接近 400%）。
- 性格优先取 `Natures`，没有就从 `Spreads` 的 `"Modest:32/0/0/32/2/0"` 前缀聚合。
- 努力值本身就是 Champions 的 0–32 SP 体系，直接入库。

**已验证**：用 2026-10 的实时文件重跑，榜首仍是 `primarina 38.88%`、样本 `87,848`、Top5 使用率变化 `0.00pp`，名次表与节奏完全一致；78 只里 65 只的所有百分比逐位相同，其余 13 只仅差 0.01% 级别的性格/特性条目（新旧数据的取舍阈值不同，不影响展示）。

### 2.2 双打使用率

默认沿用现有数据（Limitless 赛事统计，带「队伍数 / 胜率」）。如果想统一到 Smogon：

```bash
node scripts/update-data.js usage --doubles smogon --doubles-format gen9championsvgc2026regmc
```

注意 Smogon VGC 没有「胜率 / 队伍数」，页面会自动改为显示「样本 N」（`detail.js` / `rankings.js` 已做兜底）。

### 2.3 图鉴：OP.GG

| 页面 | 拿到什么 | 体积 |
| --- | --- | --- |
| `/pokedex` | 352 只宝可梦（属性、种族值、特性、招式、规则、形态） | ~2 MB |
| `/moves` | 920 条招式（属性/分类/威力/命中/PP/效果） | ~9 MB |
| `/abilities` | 314 条特性 | ~3 MB |
| `/items` | 201 条道具 | ~2 MB |

页面是 Next.js App Router，数据在 `self.__next_f.push([1,"…"])` 的 RSC 流里，脚本会拼接后按 `"pokemon":[…]` 提取，并缓存到 `.cache/opgg/`，第二次不再下载。

**默认策略（保守，避免把人工润色过的中文名覆盖掉）**：

- 宝可梦的**游戏数据**（属性、种族值、特性、招式、规则）以线上为准；
- **名称**默认保留现有译名，加 `--names` 才用线上名称；
- **派生字段**（图鉴号、形态分类、标签、排序、精灵图路径）沿用现有值，新增宝可梦才按规则推导；
- **字典**（招式/特性）只增不删，新增条目自动从 OP.GG 补中文名与说明；
- 「能力值/属性/特性完全相同、只有性别差异」的形态默认跳过（否则图鉴里会出现重复条目），加 `--include-gender-forms` 可收进来。

首次实测差异：`348 → 348 只`，新增招式 `pound（拍击）`，只有 `politoed`、`archaludon` 的招式表发生变化，规则与数量都不变——这类小改动正是这个脚本要帮你自动发现的。

## 3. 标准更新流程

```bash
# ① 看现状
node scripts/update-data.js status

# ② 看差异（不写文件）
node scripts/update-data.js usage --dry-run
node scripts/update-data.js pokedex --dry-run

# ③ 写入
node scripts/update-data.js usage
node scripts/update-data.js pokedex

# ④ 自检
node scripts/update-data.js check      # 数据自洽：引用、计数、越界、精灵图 + 代码包体积
node scripts/validate.js               # 代码结构：组件/事件/样式/路由
node scripts/smoke.js                  # 运行时：106 项断言
node scripts/preview.js                # 重新生成预览图，肉眼过一遍
node scripts/report-size.js            # 只看代码包体积（上传前必看）

# ⑤ 开发者工具里预览 → 上传 → 提审
```

`data/*.js` 是单行 JSON，写入后 git diff 会显示整行变化。想只看真实差异，用：

```bash
node scripts/update-data.js usage --dry-run     # 结构化差异报告
```

## 3.5 上传报「源码包超出最大限制」怎么办

报错长这样，`source size` 一般会比项目实际大小大很多：

```
Error: 源码包超出最大限制, source size 4478KB exceed max limit 2MB
```

**根因**：开发者工具编译时会用 Babel 把 ES6 转 ES5，Babel 的代码生成器会把**巨大的对象/数组字面量重新排版**（每个字段一行 + 缩进）。本项目实测：

| 文件 | 源文件 | 旧写法编译后 | 现写法编译后 |
|---|---|---|---|
| `data/pokedex.js` | 497 KB | 2837 KB（5.7 倍） | 498 KB |
| `data/usage.js` | 116 KB | 1264 KB（10.9 倍） | 117 KB |

再加上默认开启的 `uploadWithSourceMap` 会带一份 sourcemap（本项目约 2 MB），整包就冲到 4.4 MB，超过服务器 2 MB 的「源码包」上限。

**现在的写法**：`data/*.js` 统一生成成「单行 JSON 字符串 + 运行时 `JSON.parse`」，Babel 无法重排字符串内容，编译后体积 ≈ 源文件体积。**不要**手工改回多行对象字面量。

**体积自查**：

```bash
node scripts/report-size.js          # 代码 / 图片 / 压缩后估算 + 开发者工具实测编译体积
node scripts/report-size.js --json   # 机器可读
```

`report-size.js` 会读取开发者工具最近一次编译的产物缓存（`%LOCALAPPDATA%\微信开发者工具\User Data\...\WeappCompileCache`），给出「服务器看到的源码包体积」。改动数据后请先在开发者工具里按 `Ctrl+B` 编译一次，数字才准确。

**三层限制**（微信官方）：

| 限制 | 上限 | 本项目当前 |
|---|---|---|
| 单个包源码包（编译后代码） | 2 MB | 761 KB |
| 单个包压缩后 | 2 MB | 约 1.3 MB（主要是 348 张精灵图） |
| 整包合计 | 20 MB | 1.9 MB |

**如果以后又超了**，按收益排序：

1. `project.config.json` → `setting.uploadWithSourceMap: false`（已默认关闭，省约 2 MB）
2. 删掉不再使用的图片 / 把精灵图压成 96×96 PNG8（348 张约 1 MB，可省一半）
3. 拆分包：`app.json` 加 `subpackages`，把 `pages/calc`、`pages/member` 等非 tabBar 页挪进分包
4. 数据文件别回退成对象字面量——这是本项目最容易踩的坑

## 4. 推荐做法：使用率走远程热更新

适用：使用率每月变，但不想每月提审。

```bash
node scripts/update-data.js publish --out dist/usage.json
```

生成的 JSON 长这样（服务端只认 `version` 比本地新）：

```json
{ "version": "2026-12-02.1", "data": { "META": {...}, "RANKINGS": {...}, "USAGE": {...} } }
```

步骤：

1. 把 `dist/usage.json` 上传到任意 HTTPS 静态托管：对象存储（COS/OSS）、CDN、GitHub Pages 都可以。
2. 微信公众平台 → **开发设置 → 服务器域名 → request 合法域名**，把该域名加进去（必须 HTTPS，且不能带端口）。
3. 修改 `config.js`：

   ```js
   module.exports = {
     usageRemote: {
       enabled: true,
       url: 'https://your-cdn.example.com/champions/usage.json',
       timeout: 6000,
       maxAge: 6 * 60 * 60 * 1000   // 6 小时内不重复请求
     }
   }
   ```

4. 重新上传发布**一次**（只是为了让 `config.js` 生效）。
5. 以后每个月只需：`update-data.js usage` → `publish` → 覆盖上传那个 JSON。用户下次打开就是新数据，**不用提审**。

注意：

- `version` 必须比本地大（字符串比较），脚本默认用当天日期 `2026-12-02.1`，同一天多次发布请手动 `--version 2026-12-02.2`。
- 请求失败/超时/JSON 不合法时，小程序会**静默回落**到内置数据，不会白屏或报错。
- 远程数据只覆盖 `META / RANKINGS / USAGE`，图鉴仍然走版本发布。

## 5. 自动化（可选）

### 5.1 Windows 计划任务（每月 2 号跑一次）

Smogon 每月初发布上月数据，可以在月底/次月初自动拉取并生成热更新包：

```powershell
# 建一个每日 09:00 的任务（脚本内部会判断是否有新月份）
schtasks /Create /TN "Champions数据更新" /SC DAILY /ST 09:00 ^
  /TR "cmd /c cd /d E:\ds工作区\PokemonChampions && node scripts/update-data.js usage && node scripts/update-data.js publish --out dist/usage.json"
```

再把 `dist/usage.json` 同步到 CDN（`coscmd`/`ossutil`/`rclone` 任选）。想只在有新数据时才上传，可以先跑：

```bash
node scripts/update-data.js usage --dry-run | findstr "0.00pp" >nul || (更新并上传)
```

### 5.2 云开发（最省心，但需要开通）

微信云开发可以完全不依赖自己的服务器：

1. 云函数里跑同样的抓取逻辑（Node 环境，可直接复用 `scripts/lib/*`），定时触发器每月执行；
2. 把结果写进云数据库；
3. 小程序端改用 `wx.cloud.database()` 读，不再需要配置 request 域名。

代价是要开通云开发并按量计费，且首次改造涉及 `usage-service.js`。当前用的「CDN + JSON」方案已经够用，除非你想彻底摆脱手动流程。

## 6. 常见问题

**Q：`update-data.js usage` 卡很久？**
Smogon 的 chaos JSON 有 2–3 MB，慢速线路实测约 150 秒。脚本默认超时 4 分钟，并把原始文件缓存在 `.cache/smogon/`，第二次直接读缓存；要强制重下加 `--refresh`。

**Q：报「请求失败 … aborted」？**
网络超时。重试一次，或确认是否能直连 `www.smogon.com`（本机实测**不走代理**才通，走代理反而失败）。

**Q：OP.GG 报「没有找到 "pokemon" 数组」？**
页面结构变了。脚本按 RSC 流里的 `"pokemon":[...]` 定位，属于对页面结构的强依赖；到 `scripts/lib/opgg.js` 调整 `pageArray()` 的 key 或解析方式即可。加 `--refresh` 先排除缓存问题。

**Q：有宝可梦/招式没匹配上？**
报告里会列出未识别项（例如 `Tauros-Paldea-Blaze`）。在 `scripts/lib/names.js` 的 `OVERRIDES` 里加一条 `英文名压缩形式: 项目 key`，例如 `taurospaldeablaze: 'tauros-paldean-blaze'`。

**Q：更新后图鉴变大了，会不会超包体？**
主包上限 2 MB（压缩后）。当前 `data/pokedex.js` 约 500 KB、精灵图 1 MB，仍有余量。加新宝可梦时用 `--sprites` 补图，单张约 3 KB。

**Q：能不能只改一两处数据，不跑全量？**
可以，`data/*.js` 就是普通模块，手动改完跑 `node scripts/update-data.js check` 校验即可。但改完记得同步 `META.updated`（脚本会自动写当天日期）。

**Q：怎么确认更新没把老数据改坏？**
`node scripts/update-data.js selftest` 会用现有数据回写一遍，逐字节比对生成格式；`check` 校验引用完整性；`smoke.js` 有 106 项运行时断言；`preview.js` 出预览图人工过目。
