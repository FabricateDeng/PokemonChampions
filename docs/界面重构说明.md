## 1. 一句话结论

把"展示型页面"改成了"工具型页面"：**四个 tab 承载四个目标，首屏直接给内容，选择器从原生 picker 换成搜索面板，每页都有明确的下一步**。

| 维度 | 改造前 | 改造后 |
| --- | --- | --- |
| 主导航 | 无 tabBar，全部靠 `navigateTo` 层层跳转 | 原生 tabBar：图鉴 / 榜单 / 队伍 / 我的（`R2.1`） |
| 页面数 | 10（含分包 5 页） | 9，全部在主包，无分包 |
| 首屏内容 | 约 1046rpx 装饰与筛选后才出现卡片，第一屏只露出不到一行 | 导航 92px + 筛选区 196px，首屏可见 2 行 / 4–6 条卡片（`R3.1`） |
| 筛选器 | 3 个原生 `picker` + 收藏 + 清除，塞在一条横向滚动条里 | 属性 chip 就地可选，世代/形态/排序/收藏收进一个"筛选"面板（`R7.4`/`R7.7`） |
| 招式选择 | 原生 `picker` 滚动 60+ 条 | 底部面板 + 搜索 + 分类筛选（`R7.8`） |
| 道具选择 | 原生 `picker` 滚动 167 条 | 底部面板 + 搜索 |
| 详情页 | 看完即止，没有任何出口 | 底部常驻：收藏 / 加入队伍（`R8.6`） |
| 最小字号 | 13rpx（多处 13–20rpx） | 22rpx（`R5.1`） |
| 强调色 | 金色 + 青色 + 6 种数值色 + 18 种属性色混用 | 单一琥珀色；属性色只出现在属性标签/相性（`R6.2`/`R6.3`） |
| 装饰 | Hero、网格背景、双层轨道、精灵球插画、每卡光晕、阴影 | 全部移除；仅保留 1rpx 描边分层（`R4.4`/`R4.5`） |
| 英文装饰字 | POKÉMON CHAMPIONS / META SNAPSHOT / TEAM BUILDER / DAMAGE CALC / MOVE DEX / TEAM CONFIG / ADD TO TEAM / DATA UPDATE | 全部移除，只保留数据来源名（`R5.4`/`R9.5`） |
| 破坏性操作 | 队伍卡片上直接放"删除"；成员卡片上"编辑/移除"并排 | 删除收进队伍编辑页的"⋯"面板，二次确认；成员移除在页面底部（`R8.3`） |

## 2. 问题诊断（改之前到底哪里不顺手）

按规范条款归类，每条都对应代码里的事实：

### 2.1 目标不明确（`R3.1` / `P1` / `P2`）

- `pages/index/index.wxml` 首屏是 Hero（kicker + 54rpx 标题 + 精灵球插画 + 3 个数字 + 3 个入口按钮 + META 速览卡）+ 两张工具卡 + 搜索提示，合计约 1046rpx；图鉴卡片要滚动才出现。
- 一个页面同时承担：品牌展示、环境速览、工具入口、图鉴检索。用户打开后不知道"该先干什么"。
- `pages/moves/moves` 又用同样的 Hero 结构（`MOVE DEX`）重复了一遍。

### 2.2 可选项被藏起来（`R3.1` / `P3`）

- 世代、形态、排序三个筛选是原生 `picker`，各自只是一个 chip，用户必须逐个点开才知道有哪些选项。
- 这 5 个 chip（世代/形态/排序/收藏/清除）放在 `scroll-view` 横向滚动里，屏幕外的选项等于不存在。

### 2.3 用错控件（`R7.8`）

- `packages/tools/pages/member`：招式用 `picker`（一只宝可梦最多 66 个招式）、道具用 `picker`（167 项）、性格用 `picker`（25 项）。滚动找招式是这套工具里最痛的一步。
- `pages/calc/calc`：用 6 个原生 `switch` + 4 个 `picker` 铺满一屏，结果卡被挤到最底部。

### 2.4 死路与断点（`R8.6`）

- `pages/detail/detail` 有四个 tab，内容很全，但**没有任何操作**：看完一只宝可梦无法加入队伍、无法进入伤害计算。
- 收藏只能靠列表页横条里的一个 chip 进入，没有集中的收藏视图。

### 2.5 主次不分（`R7.1` / `R8.3`）

- 队伍卡片右上角直接挂"删除"文字按钮，和"进入编辑"同屏同级。
- 成员卡片并排"编辑 / 移除"。
- 首页里"使用率榜""招式库""说明"三个按钮同样大小，只有榜是主操作。

### 2.6 可读性与视觉重量（`R5.1` / `R6.2` / `R4.4`）

- 大量 13–20rpx 的字（`.quick-kicker` 13rpx、`.meta-kicker` 14rpx、`.foot-label` 15rpx、`.search-tip` 19rpx 等），在真机上等于 6.5–10px。
- `letter-spacing: 3.2rpx` 的英文小字 + `font-weight 700`：看起来"高级"，但读不清。
- 每张卡片都有 `linear-gradient` 背景 + `radial-gradient` 光晕 + `box-shadow`，页面里同时出现金色、青色、6 种数值色、18 种属性色。

### 2.7 导航结构（`R2.1` / `R2.2`）

- 工具页放在 `packages/tools` 分包里，入口散落在首页和队伍页；`navigateTo` 链路达到 4 层（首页 → 队伍 → 成员 → 计算）。
- 没有 tabBar，用户在任意子页都无法"回主页再换个方向"。

## 3. 新的信息架构

```
tabBar
├── 图鉴  pages/index        搜索 + 属性筛选 + 筛选面板  →  详情
│                            分段：宝可梦 / 招式（招式库并入此处）
├── 榜单  pages/rankings     单打 / 双打，TOP3 + 4–50  →  详情（使用率视图）
├── 队伍  pages/teams        队伍列表  →  队伍编辑  →  选择宝可梦  →  成员配置
│                                              └──→  伤害计算
└── 我的  pages/profile      收藏 / 队伍入口 / 数据说明 / 来源 / 免责
```

改动要点：

1. **"招式库"不再是独立页面**，成为图鉴页的第二视图（分段控件）。两者都是"查一个东西"，不该占两个入口（`P2`）。
2. **"关于"并入"我的"**，数据来源与免责不再出现在业务首屏（`R9.4`）。
3. **工具模块从分包迁回主包**：`packages/tools/*` → `pages/*`。原因：tabBar 页面必须在主包（`R2.1`），而"队伍"必须是一级入口。主包体积仍然可用（本地代码包约 1.9MB，未压缩；小程序上传时会压缩）。
4. **导航深度 ≤ 3**：图鉴 → 详情；队伍 → 队伍编辑 → 成员配置（选择宝可梦用 `redirectTo` 接成员配置，不再多一层）。

## 4. 设计体系落地

### 4.1 令牌（`app.wxss` 顶部）

```css
--bg #0a0e14   --surface #131a24   --surface-2 #1a222e
--line rgba(255,255,255,.08)   --line-strong rgba(255,255,255,.16)
--text #e8edf5   --text-2 #98a3b4   --text-3 #6a7585
--brand #f2c455  --brand-soft rgba(242,196,85,.14)  --brand-line rgba(242,196,85,.4)  --brand-ink #221902
--danger #f0616f  --danger-soft rgba(240,97,111,.12)  --success #3fbf9a
--r-card 24rpx   --r-ctrl 14rpx   --r-tag 8rpx
```

页面 WXSS 里不出现任何新的十六进制色值——这条已经由 `scripts/validate.js` 自动检查（`R6.1`）。

### 4.2 字号阶梯

只用 6 档：40 / 36 / 30 / 28 / 24 / 22（rpx）。改造前的最小 13rpx 一律提到 22rpx 以上。

### 4.3 公共组件（4 个）

| 组件 | 职责 | 对应规范 |
| --- | --- | --- |
| `nav-bar` | 自定义导航：状态栏 + 胶囊避让 + 返回 + 标题/副标题 | `R2.4` / `R2.5` / `R10.5` |
| `segmented` | 2–4 段视图切换，选中态 = brand 14% 底 | `R7.5` |
| `sheet` | 底部面板：抓手、标题、完成、可滚动内容、遮罩 | `R7.7` |
| `empty-state` | 空态：图标 + 标题 + 说明 + 一个"能解决问题"的按钮 | `R7.9` |

组件统一 `styleIsolation: apply-shared`，直接复用 `app.wxss` 的令牌与按钮/chip/列表样式，避免每个组件复制一遍样式。

### 4.4 公共工具（`utils/`）

| 文件 | 作用 |
| --- | --- |
| `system.js` | 一次性读取状态栏/胶囊尺寸，导航栏高度不再各页各算 |
| `routes.js` | 所有页面路径集中定义，改名不会再留下死链 |
| `format.js` | 百分比/千分位/大数/图鉴编号格式 |
| `mon.js` | 图鉴与招式的归一化视图模型（启动时构建一次，`R11.3`） |
| `favs.js` | 收藏读写去重，三处页面不再各自操作 storage |
| `ui.js` | 属性色/分类/威力命中 PP 文本/种族值排名 |

## 5. 逐页改造

### 5.1 图鉴（`pages/index`）

**改之前**：Hero + 工具卡 + 搜索 + 属性条 + 5 个筛选 chip + 结果条 → 卡片在 587px 处才开始。

**现在**（`docs/preview/a-图鉴.png`）：

- 吸顶区（`position: sticky`）：搜索 88rpx → 分段（宝可梦/招式）→ 属性 chip 横滑 → 「筛选 · 按图鉴编号」一行。滚动时始终可改条件（`R3.2`）。
- 筛选面板把世代（10）/形态（5）/排序（4）/只显示收藏收进一个底部面板，选项**一眼看全**，点选即时生效，面板不跳页（`R7.7`）。
- 卡片：图鉴号 + MEGA 标记 + 收藏星（`catchtap` 不触发跳转）+ 精灵图 148rpx + 名称 + 属性标签，两列。
- 招式视图：单列行式，名称 + 属性 + 分类 + 先制 + 威力/命中/PP + 学习面 + 说明（说明直接展示，不再"点开看"，去掉一层隐藏交互）。
- 空态：`empty-state` + 「清除筛选」，不是一句"没有结果"了事（`R7.9`）。

**关键交互**：搜索 150ms 防抖；切换视图清空关键词但保留各自的属性筛选；`onShow` 只刷新收藏状态、不清筛选（`R8.5`）。

### 5.2 详情（`pages/detail`）

**改之前**：三屏 Hero + 四个 tab，看完没有任何操作。

**现在**（`docs/preview/b-详情.png`）：

- 紧凑头部：名称 / 属性 / 图鉴号·世代·种族值·规则 + 精灵图，约 200rpx。
- 三个视图：数据（种族值 + 排名 + 属性相性 + 特性）/ 招式（分类 chip + 招式列表）/ 使用率（单打·双打 chip + 排名摘要 + 特性/道具/性格/努力值/招式携带率）。
- **使用率覆盖全部宝可梦**：有样本的显示真实名次与百分比（含 51 名以后）；没有样本的也给出"未上榜 · ＜ 3.32%"（该赛制 TOP50 的截断值）与样本量，并说明为什么不提供配置分布（`docs/preview/c-榜单.png` 第三张）。
- 底部常驻操作栏：`☆ 收藏` + `加入队伍`。加入队伍弹出队伍列表面板，直接落到第一个空位并提示"已加入「xx」第 N 位"；重复加入/队伍已满都有明确反馈。
- 使用率用 chip 切换赛制，避免和页签分段控件叠成两排（`R7.5` 补充条款）。

### 5.3 榜单（`pages/rankings`）

- 单打/双打分段；数据来源与样本量合并成一行（原来是两行小字）。
- 范围两档：`TOP 50` 与 `全部精灵`。全部档把 348 只全部列出——有样本的按真实名次排（含 51–216 名），完全无样本的排在后面并标注"无样本 · ＜ 截断值"，分页 50 条（`docs/preview/c-榜单.png`）。
- TOP3 用三张小卡强调，4 名之后用列表：名次、精灵、名称 + 属性 + 样本、使用率 + 相对条形。
- 点任意一行进详情并直接落在"使用率"视图（带 `tab=usage&format=...`），不用用户再点一次。

### 5.4 队伍（`pages/teams` / `pages/team`）

- 列表页只做一件事：进入队伍。删除从卡片上移除，收进队伍编辑页的"⋯"（`R8.3`）。
- 队伍编辑：队名就地可改（失焦自动保存）、6 个槽位、每个成员显示属性/特性/道具/性格/四招。空槽是虚线"添加第 N 位"。
- 底部固定「伤害计算」，不足 2 只时置灰并给 toast 说明。

### 5.5 选择宝可梦（`pages/picker`）

- 搜索 + 属性 chip + 列表行（精灵、名称、图鉴号、属性、右侧"+"）。
- 已在队伍中的宝可梦显示「已在队伍」并禁止重复选择。
- 选中后 `redirectTo` 到成员配置，返回时直接回到队伍编辑（不产生多余页面层级）。

### 5.6 成员配置（`pages/member`）

**改之前**：`picker` × 6（特性/道具/性格/4 招式）+ 6 个 SP 加减。

**现在**（`docs/preview/e-配置与计算.png`）：

- **能力值与努力值合并成一张表**（`R7.12`）：每行 = 名称（含性格 `+/−` 标记）→ 能力值输入框 → 努力值步进器。改努力值，同行能力值立刻变；填能力值，自动反解努力值（`R7.11`）。
- 能力值、努力值都支持**键盘直接输入**：能力值 `type="number"` 失焦/确认时反解；努力值输入过程即合法即写入，失焦时截断越界值并归一化文本。
- 反解拿不到目标值时回填最接近的一档并提示"已按努力值取最接近的一档：xxx"，不静默改动；总和 66 用尽时按剩余点数封顶。
- 特性 / 道具 / 性格：点行 → 底部面板。道具面板带搜索（167 项），性格带修正说明，当前项打勾。
- 招式：4 个槽位 → 底部面板，**搜索 + 物理/特殊/变化分类**，重复招式会被拒绝并提示。
- 全部自动保存，页面标注"自动保存"，不弹保存按钮（`R8.4`）。
- 移除成员放在页面最下方、独立红色描边按钮 + 二次确认。

### 5.7 伤害计算（`pages/calc`）

**改之前**：两个整宽卡片 + 4 个 picker + 6 个 switch，结果卡在最底部，要滚动才看得到。

**现在**：

- 攻击方/防守方并排两卡（精灵、名称、特性或道具、三项关键能力值）。
- 招式直接列攻击方已配置的 4 个招式 chip，不用再开选择器。
- 暴击/反射壁/光墙/灼伤/帮助/满 HP 用 chip 开关；天气与能力等级收进「更多条件」，默认折叠。
- **结果常驻底部**：招式、伤害区间、百分比、效果、乱数击杀率、至少几击。改任何条件即时刷新（`R8.6`）。
- 无队伍/人数不足时用 `empty-state` 直接给出"去创建队伍 / 编辑这支队伍"。

### 5.8 我的（`pages/profile`）

- 收藏网格（4 列）+ 空态引导去图鉴。
- 我的队伍入口、数据说明、数据来源、免责声明。
- 数据说明第一行是**当前规则**（`规则 M-C（10.05 – 11.05）`，取自使用率样本的赛制），区块标题右侧还有一枚 `规则 M-C` 徽章；另有一行说明使用率覆盖范围（榜单收录 78 只 / 其余 270 只标注未上榜）。
- 原来 `pages/about` 的 5 个长信息块压缩成 8 行"标签—值"，次要信息降到 24rpx。

## 7. 怎么验证的

没有微信开发者工具的环境，所以做了两层验证：

### 7.1 静态校验（`node scripts/validate.js`，当前通过）

12 类检查，任一失败即非零退出：

1. 所有 JSON 可解析
2. 所有 JS 通过 `node --check`
3. `app.json` 页面文件齐全、tabBar 页面在主包、tabBar 图标存在
4. 页面目录里没有未注册的页面
5. WXML 标签闭合匹配
6. 自定义组件已在 `usingComponents` 注册且文件齐全
7. `bindtap` / `catchtap` 绑定的方法在页面 JS 里存在
8. `{{变量}}` 都在 `data` 或循环变量里声明
9. WXML 用到的 class 在 `app.wxss` / 页面 wxss / 组件 wxss 里有定义
10. `var(--x)` 令牌都已定义
11. 页面 wxss 无裸十六进制色值（`R6.1`）
12. `require()` 路径可解析、路由字符串指向已注册页面、本地资源存在

（这套检查本身做过故障注入测试：故意制造 6 类错误，均能被报出。）

### 7.2 运行时冒烟测试（`node scripts/smoke.js`，当前 106 项断言全过）

打桩 `wx` 后真实执行每个页面的 `onLoad` / `onShow` 与主要事件：筛选、搜索、排序、收藏、翻页、切换视图、切换赛制、加入队伍、修改队名、增减努力值、选道具/性格/招式、切换计算条件……断言不抛异常且数据合理。

它抓到两个静态检查和预览都发现不了的真实缺陷：
