# 小程序界面与交互设计规范

> 版本 v1.0 · 适用范围：本项目及后续所有微信小程序
> 单位：`rpx`（750rpx = 屏宽）。文中所有数值均为默认值，例外必须在本页备注理由。
> 规则编号（如 `R3.2`）用于评审引用，代码注释可直接引用编号。

---

## 0. 为什么需要这份规范

本项目初版存在的问题，几乎都不是"配色不好看"，而是**结构问题**：

| 现象 | 本质 |
| --- | --- |
| 首屏被巨型 Hero、装饰网格、光晕、英文 kicker 占满，搜索要下滑才出现 | 装饰优先级高于任务 |
| 3 个原生 `picker` + 收藏 + 清除塞进一条横向滚动条 | 可选性被藏在横向滚动里，靠猜 |
| 招式选择用原生 `picker` 滚动 80+ 项 | 用错控件 |
| 详情页看完没有任何"下一步" | 死路页面 |
| 队伍卡片上直接放"删除"，成员卡片上并排"编辑/移除" | 主操作与破坏性操作同级 |
| 大量 13–20rpx 字号、letter-spacing 3rpx 的英文小字 | 可读性让位于氛围 |
| 每个区块都有自己的渐变、描边、光晕、阴影 | 视觉重量无层级 |

因此本规范的目标不是"更好看"，而是**让用户 3 秒内知道在哪、能做什么、下一步点哪里**。

---

## 1. 五条原则

- **P1 任务优先**：首屏归任务，装饰不得占用可交互区域。任何不承载信息的元素（网格、光晕、轨道、装饰圆）不得挤占首屏。
- **P2 一个屏幕一个目标**：每页只回答一个问题。若并列两个目标，用分段控件并列，而不是上下堆两套 UI。
- **P3 可见即可用**：可选项必须一次性可见或由一个明确入口收拢；**禁止**把筛选项/操作藏在横向滚动条的可视区之外。
- **P4 主次分明**：同一屏幕只允许一个主按钮（实心强调色）。破坏性操作降级为次级样式，并放在二级入口。
- **P5 明确结局**：每个页面结束处必须有出口或下一步；不存在"看完就走不了"的页面。

## 2. 信息架构与导航

### R2.1 主导航用原生 tabBar，2–5 项
- 用原生 `tabBar`，不要自绘底部导航（自绘会丢掉切换动画、返回堆栈、无障碍与 `reLaunch` 语义）。
- 项数 3–5；超过 5 个说明有二级内容混进了主导航。
- tab 名称 2–4 个字，动宾结构优先（"图鉴""榜单""队伍""我的"）。
- **tabBar 页面必须在主包**：主包只放"壳 + 首屏数据"，重模块放分包，但 tab 目标不能放分包。

### R2.2 层级不超过 3 层
`tab 页 → 列表/编辑页 → 选择器/详情页`。超过 3 层时改用同页分段或底部面板（`R7.7`）。

### R2.3 返回永远可用
- 非 tab 页必须提供返回；`getCurrentPages().length === 1` 时回落到 `reLaunch` 首页。
- 禁止用 `wx.navigateTo` 打开 tab 页，用 `wx.switchTab` 或 `wx.reLaunch`。

### R2.4 页面标题 = 用户语言
导航标题用中文名词短语，**不加英文 kicker、不加编号**，长度 ≤ 8 字，超长省略。

### R2.5 平台约束优先于设计稿
自定义导航栏右侧必须为胶囊按钮让位（内容区右内边距 ≥ 200rpx）；页面底部必须计入
`env(safe-area-inset-bottom)` 与 tabBar 高度。

## 3. 首屏与信息密度

### R3.1 首屏法则（硬性）
首屏（不作任何滚动可见区域）必须包含：
1. 我在哪（标题）；
2. 最重要的一条主操作（搜索框或主按钮）；
3. 至少 3 条内容/结果预览。

**禁止**在列表页顶部放高度 > 200rpx 的纯装饰区。项目初版首页 Hero + 工具卡 + 提示语合计约 1046rpx（≈523px），首屏连一行图鉴卡片都放不下，属于严重违规。

### R3.2 吸顶
列表页的搜索与筛选栏使用 `position: sticky` 吸顶（top = 导航总高），保证滚动中随时可改条件。

### R3.3 密度基准
| 内容 | 单屏可见条数 | 行高 |
| --- | --- | --- |
| 双列卡片 | ≥ 6（3 行） | 220–280rpx |
| 单列列表行 | ≥ 6 | 104–120rpx |
| 表单行 | ≥ 5 | 96–112rpx |

### R3.4 分页
列表先渲染 30 条，`onReachBottom` 追加；到达末尾显示"共 N 条"，不再显示"继续上滑"这类无信息文案。

## 4. 栅格、间距、圆角、层级

### R4.1 间距 8 栅格
只用 `8 / 12 / 16 / 24 / 32 / 40 / 48`（rpx 的 4 倍数列也允许 `4 / 20 / 28`）。禁止随手 `13rpx`、`17rpx` 这类数值。

### R4.2 页边距
页面左右统一 `24rpx`；卡片内边距 `24rpx`；同级卡片间距 `16rpx`；不同区块间距 `32rpx`。

### R4.3 圆角三档
- 大容器/卡片：`24rpx`
- 控件（按钮、输入框、chip）：`14rpx`
- 小标记（标签、徽章）：`8rpx`

禁止大面积使用全圆角（`999rpx`）。全圆只用于头像、计数徽章、开关。

### R4.4 层级只用三层
`bg`（页面）→ `surface`（卡片）→ `surface-2`（卡内浮起：输入框、选中态、面板）。
层级差异靠**底色 + 1rpx 描边**表达，**不靠**阴影、光晕、渐变边框。全局最多保留
一处阴影，用于固定底栏/底部面板（`0 -8rpx 32rpx rgba(0,0,0,.35)`）。

### R4.5 装饰预算
每屏装饰性元素（渐变、网格、光晕、插图）≤ 1 个，且不得与文本重叠影响对比度。

## 5. 字体与数字

### R5.1 字号阶梯（只用这 6 档）
| 语义 | 字号 | 行高 | 字重 |
| --- | --- | --- | --- |
| 数字强调 | 40–44 | 1.1 | 700 |
| 页面主标题 | 36 | 1.2 | 700 |
| 区块标题 | 30 | 1.3 | 600 |
| 正文 | 28 | 1.45 | 400 |
| 辅助说明 | 24 | 1.4 | 400 |
| 最小字号 | 22 | 1.35 | 500 |

**硬性下限 22rpx**。任何 < 22rpx 的文字都不可交付（初版存在 13–20rpx 的文字，属不可接受）。

### R5.2 字距
中文不使用 `letter-spacing`；仅纯英文/数字标签可用 `0.5–1rpx`。禁止 `3rpx` 以上的字距。

### R5.3 数字对齐
所有会纵向排列的数字（种族值、百分比、排名）使用 `font-variant-numeric: tabular-nums`。

### R5.4 中英混排
界面文案以中文为主。英文只用于**数据来源名**（Smogon/Limitless）与品牌标识，且不与中文标题并列堆叠。

## 6. 色彩

### R6.1 令牌化
颜色只能引用令牌（CSS 变量或 `app.wxss` 类），页面 WXSS 内不得出现新的十六进制色值。

```css
--bg: #0a0e14;        --surface: #131a24;   --surface-2: #1a222e;
--line: rgba(255,255,255,.08);
--text: #e8edf5;      --text-2: #98a3b4;    --text-3: #6a7585;
--brand: #f2c455;     --brand-ink: #221902;
--danger: #f0616f;    --success: #3fbf9a;
```

### R6.2 强调色配额
一屏内强调色最多出现在 **1 个主按钮 + 1 组当前选中态 + 数据高亮**。同一区域不得出现两种强调色。

### R6.3 分类色用于表达分类，不用于装饰
属性色（草/火/水…）只在属性标签、属性条上出现，用"14% 透明底 + 该色文字"表达；**不加描边**。

### R6.4 对比度
正文与背景对比度 ≥ 4.5:1，辅助文字 ≥ 3:1。深色底上不使用 `#333` 级别的深灰文字。

## 7. 组件规范

### R7.1 按钮
| 类型 | 高度 | 样式 | 用途 |
| --- | --- | --- | --- |
| 主按钮 | 88 | 实心 brand，字色 brand-ink | 每屏至多 1 个 |
| 次按钮 | 88 | surface-2 底 + 1rpx 描边 | 备选动作 |
| 文字按钮 | 64 | 无底色，brand 文字 | 轻量跳转 |
| 危险按钮 | 88 | 文字 danger / 面板内实心危险色 | 删除，必须二次确认 |

按钮宽度：主操作撑满或 ≥ 50% 屏宽；同一行按钮间距 `16rpx`；按钮文案 2–6 字动词短语。

### R7.2 点击反馈
所有可点元素必须设置 `hover-class`（缩放 0.98 或底色加深），并在 100ms 内可见。
禁止无反馈的可点区域。

### R7.3 输入框
高度 88rpx，`surface-2` 底，左侧图标，右侧清除按钮（有内容时）。
搜索类输入必须：`confirm-type="search"`、输入节流 120–200ms、清空按钮可一键重置。

### R7.4 Chip（标签式选项）
高度 64rpx，圆角 14rpx，字号 26rpx。
- 未选：`surface-2` 底 + `--line` 描边 + `--text-2`；
- 已选：`--brand` 14% 底 + brand 文字 + brand 40% 描边。
可多选时已选态在文字前加 `✓`。**横向 chip 组必须是唯一入口，不得再叠加其他筛选**。

### R7.5 分段控件（Segmented）
高度 72rpx 的 track（`surface-2`）+ 内嵌等宽分段；选中段使用 **`brand` 14% 底 + brand 文字**，
与 chip 选中态保持同一套视觉语言（不要用"凹陷"或纯描边表达选中）。
用于**同一对象的不同视图**（宝可梦/招式、数据/招式/使用率），段数 2–4。
段数 ≥ 5 时改用 chip 组。若同页已有分段控件，第二处切换改用 chip 组，避免两层分段叠加。

### R7.6 列表行
单行结构固定为：`[次要信息 64rpx] [图/头像 88rpx] [主文本 + 副文本 自适应] [右侧数值/箭头]`，
行高 104–120rpx，行间用 1rpx 分隔线，**不用每行一张卡片**。
整行只有一个主操作；行内次级操作最多 1 个，且不得与破坏性操作并排。

### R7.7 底部面板（Sheet）
用于：多条件筛选、长列表选择（> 8 项）、行内次级菜单、需要搜索的选择。
- 遮罩 `rgba(0,0,0,.55)`，面板顶部圆角 `28rpx`，最大高度 80vh，内容区可滚动；
- 顶部有 72rpx 抓手条 + 标题 + 右侧"完成/关闭"；
- 面板内选择即时生效，关闭即返回列表（不额外跳页）；
- 出现/消失用 160ms 位移过渡，遮罩淡入。

### R7.8 原生 `picker` 的使用边界
仅允许用于：≤ 8 项的短枚举、日期/地区选择。
**超过 8 项一律改底部面板 + 搜索**。项目初版把 80+ 个招式塞进原生 picker，属违规。

### R7.9 空状态
结构：`图标（≤ 120rpx，线性，非插画） + 一句标题 + 一句说明 + 一个动作按钮`。
动作按钮必须是"能解决问题的那一步"（清除筛选 / 新建队伍 / 去图鉴），不能只是"知道了"。

### R7.10 反馈
| 场景 | 方式 |
| --- | --- |
| 轻量成功（收藏、加入队伍） | `wx.showToast`（`icon:'none'`，700–1200ms） |
| 失败/校验 | `wx.showToast` 说明原因，或行内红字 |
| 破坏性操作 | `wx.showModal` 二次确认，确认按钮用危险色 |
| 长任务 | 行内骨架屏/加载条，不用全屏 loading |
| 自动保存 | 不弹 toast，用行内"已保存"状态 |

禁止同一操作同时弹 toast 和 modal。禁止用 toast 描述需要用户决策的信息。

### R7.11 数值输入与派生值
- 任何用户会反复调整的数值（能力值、努力值、数量）都要支持**键盘直接输入**，不能只给 `+/−` 步进；步进器用于微调，输入框用于跳变。
- 当某个数值是**派生出来的**（如能力值 = 种族值 + SP + 性格），允许直接填目标值，但必须：
  1. 反解出最接近的底层参数并写库；
  2. 无法精确等于目标时，回填实际值并提示"已取最接近的一档"，不静默篡改；
  3. 受总量约束时按上限截断并说明原因。
- 输入过程中的合法值即时生效（不重写输入框文本，避免光标跳动），非法/越界值在失焦时归一化。

### R7.12 同源数据同屏
派生值与它的来源参数（能力值 ↔ 努力值、总价 ↔ 单项）必须放在**同一张表、同一行**，改一边立刻看到另一边变化，不要让用户在两块区域之间来回滚动比对。

## 8. 交互规则

### R8.1 点击区尺寸
主操作 ≥ 88×88rpx；次级 ≥ 64×64rpx。图标按钮通过 `padding` 扩大热区，视觉尺寸可小于热区。

### R8.2 首次点击即生效
除破坏性操作外，点击立即产生结果，不设"确认"步骤。按钮文案说做什么，就立即做什么。

### R8.3 破坏性操作分级
- 删除单个条目：行内不出现删除；收进"更多"面板或详情页底部；
- 删除整份数据（队伍/收藏）：`wx.showModal` + 文案写明不可恢复；
- 批量清空：必须二次确认。

### R8.4 自动保存优先
表单类页面（队伍配置、能力值）默认自动保存，页面底部注明"修改自动保存"。
只有涉及跨设备/不可逆时才用显式保存按钮。

### R8.5 状态保持
返回上一页时必须保留：滚动位置、筛选条件、输入关键词、展开项。
筛选条件存页面实例（`this.filters`），不随 `setData` 丢失；跨页返回时在 `onShow` 重算可见数量而非重置。

### R8.6 无死路
详情页/结果页必须提供至少一个"下一步"：加入队伍、进入计算、查看榜单、或返回列表的明确入口。

### R8.7 三态齐备
每个数据区域都要实现：**加载/空/有数据**。远程数据失败时降级到本地数据并**不打断用户**（不要 toast 报错）。

### R8.8 防抖与节流
搜索输入 150ms 防抖；`onReachBottom` 追加时加锁；连续点击同一按钮 400ms 内只执行一次。

### R8.9 手势
不引入自定义滑动手势（左滑删除等），微信内易与系统返回手势冲突。
需要"更多操作"时用 `R7.7` 底部面板。

## 9. 文案

- **R9.1** 按钮用动词短语："加入队伍""开始计算"，不用"确定/提交"这类无信息文案。
- **R9.2** 空态/错误文案给出下一步，不写"未知错误"。
- **R9.3** 单位与数字：百分比保留 1 位小数（<10% 保留 2 位），千分位分隔，大数用"万"。
- **R9.4** 免责与数据来源统一收在"我的 → 数据说明"，不放在业务首屏。
- **R9.5** 不用全大写英文作为区块标题；数据来源名保留原样。

---

## 10. 可访问性与平台适配

- **R10.1** 字号下限 22rpx（`R5.1`）；不依赖颜色单独传达状态（选中态同时有底色变化或 `✓`）。
- **R10.2** 图片必须有 `mode` 与固定尺寸，避免布局跳动；列表图 `lazy-load`。
- **R10.3** 所有页面底部 `padding-bottom` 计入 `env(safe-area-inset-bottom)`；有固定底栏时再加 112rpx。
- **R10.4** 支持大字体系统设置时布局不溢出（文本容器用 `flex` + `min-width:0` + 省略）。
- **R10.5** 自定义导航栏高度由 `getMenuButtonBoundingClientRect()` 实测，不写死 44。

---

## 11. 性能与包体

- **R11.1** 主包只放首页链路；工具类页面放分包，但 tab 目标必须在主包（`R2.1`）。
- **R11.2** 单页 `setData` 数据量 ≤ 100KB；长列表分页渲染。
- **R11.3** 大数组（图鉴数据）在页面 `onLoad` 只构建一次，存实例变量；`setData` 只传渲染用的精简字段。
- **R11.4** 图片走本地 `assets/` 或 CDN，单片 ≤ 60KB；tabBar 图标 81×81。
- **R11.5** 列表 `wx:key` 必须使用稳定唯一键，不用 `index`。

## 12. 交付验收清单

- [ ] 首屏包含标题、主操作、≥3 条内容（`R3.1`）
- [ ] 无装饰区挤占首屏，装饰元素 ≤ 1 处（`R4.5`）
- [ ] 主导航为原生 tabBar，2–5 项，均在主包（`R2.1`）
- [ ] 所有字号 ≥ 22rpx（`R5.1`）
- [ ] 颜色全部来自令牌，无新增十六进制色值（`R6.1`）
- [ ] 每屏 ≤ 1 个主按钮（`R7.1`）
- [ ] 所有可点元素有 `hover-class`（`R7.2`）
- [ ] 无原生 picker 长列表，> 8 项走底部面板（`R7.8`）
- [ ] 破坏性操作均二次确认，且不与主操作并排（`R8.3`）
- [ ] 筛选/搜索状态在返回后保留（`R8.5`）
- [ ] 每个数据区有空态且空态有动作（`R7.9`）
- [ ] 详情/结果页有明确下一步（`R8.6`）
- [ ] 底部安全区与 tabBar 高度已补偿（`R10.3`）
- [ ] 列表 `wx:key` 稳定（`R11.5`）

## 13. 本项目落地约定

以下为本项目（冠军图鉴）对通用规范的具体取值，后续页面照此实现。

### 13.1 导航结构
```
tabBar：图鉴 · 榜单 · 队伍 · 我的
图鉴        pages/index      宝可梦 / 招式 双视图（分段控件）
榜单        pages/rankings   单打 / 双打（分段控件）
队伍        pages/teams      队伍列表 → 队伍编辑 → 选择宝可梦 / 成员配置 → 伤害计算
我的        pages/profile    收藏 · 数据说明 · 关于
```
